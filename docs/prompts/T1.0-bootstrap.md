# Prompt para OpenCode: T1.0 bootstrap de infraestructura

> Reconstruido a posteriori desde `docs/fases/F1-flujo-critico.md` (fila T1.0)
> y el estado real del repositorio: el prompt original de T1.0 no se conservó.
> Se versiona para completar `docs/prompts/`. Rama: `main` (antes de T1.1).

## ROL
Ingeniero de plataforma. Fase F0 cerrada (ADR y contratos aceptados). No
rediseñes; si algo es ambiguo, pregunta.

## ALCANCE
1. `compose.yaml`: PostgreSQL 16 con `init: true`, volumen `pgdata` y redes
   `backend-net` y `data-net` (`internal: true`). Sin puertos publicados en el
   compose base.
2. `scripts/init-db.sh`: crea los 6 roles y las 6 BDs (`customer_db`,
   `hotel_db`, `availability_db`, `reservation_db`, `payment_db`,
   `notification_db`), revoca `CONNECT` a `PUBLIC` y fija
   `statement_timeout`, `lock_timeout` e `idle_in_transaction_session_timeout`
   por rol (ADR-0002).
3. `.env.example` con el superusuario y las 6 contraseñas de rol; `.env` fuera
   de Git; `scripts/gen_secrets.py` genera `secrets/*.txt` (ignorados por Git).
4. `Makefile`: `up`, `down`, `test`, `lint`, `clean`, `clean-all`, `deps`.
   `make up` deja PostgreSQL `healthy`.
5. Perfil de desarrollo (`compose.dev.yaml`) que publica PostgreSQL solo en
   `127.0.0.1:${POSTGRES_DEV_PORT}` (5433) para las pruebas de integración.
6. CI (`.github/workflows/ci.yml`): `ruff` + `import-linter` + tests sobre el
   stack; sin omisiones silenciosas.

## PRUEBAS
- `make up` deja PostgreSQL `healthy`.
- El rol de una BD **no** puede conectarse a otra BD (test de infraestructura).
- `docker compose config -q` y `docker compose -f compose.yaml -f
  compose.dev.yaml config -q` pasan.

## CRITERIOS DE ACEPTACIÓN
`make up`, `make test` y `make lint` en verde; 0 pruebas omitidas; secretos
solo por archivo.
