## Desviaciones justificadas

1. **`docs/prompts/T1.0` no existe**: solo se versionaron T1.1–T1.3 (`docs: prompts de tareas`). El Paso 0 pedía T1.0–T1.3; no se inventó el contenido.
2. **`CANCELLING` sin plazo**: ADR-0003 no define arista de salida para `CANCELLING`; se reintenta con backoff exponencial indefinido (no se inventó `MANUAL_REVIEW`). Requiere decisión de ADR si se quiere un tope.
3. **`/ready` = BD**: las dependencias customer/hotel son lecturas de validación, no críticas para aceptar tráfico; se documentó como aclaración en `docs/05-contratos-api.md` §1 (sin cambio de contrato).
4. **5xx/503 → `ambiguous=True`**: se corrigió el cliente para seguir literalmente el prompt (timeout, 5xx, 503 y corte de respuesta ambiguos; conexión rechazada/DNS no ambiguo). Antes del fix los 5xx se marcaban no ambiguos.
5. **Reintentos GET**: 3 intentos totales (máximo 2 reintentos) con backoff; POST sin reintentos, como exige el prompt.
6. **`httpx`**: dependencia ya contemplada en ADR-0009 y usada por payment; se añade a `pyproject.toml` del servicio.
7. **Cabecera `Idempotency-Key` en `POST /payments`**: la API de payment (T1.2) la exige; su ausencia producía 422 y dejaba la saga en `PAYMENT_PENDING`. Es cumplimiento del contrato existente, no un cambio.
8. **Relay del outbox**: no implementado (prohibido en T1.3; corresponde a F2). El evento `reservation.confirmed`/`reservation.cancelled` se escribe en la misma transacción.
9. **Prueba de stack y `make test`**: usan el override de desarrollo para publicar 5433/8101/8102; el compose base sigue sin publicar puertos.
10. **Prompts/PR**: no se creó PR remoto (el remoto `origin` solo tiene F0 y `gh` no está instalado); este informe queda versionado en la rama.
